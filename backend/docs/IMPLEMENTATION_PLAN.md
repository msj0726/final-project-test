# 구현 순서

> 최신 범위 변경: 사용자 이미지의 영상 업로드·발화/시선/자세/내용/구조 분석·타임스탬프 근거·종합 평가·우선 개선 지침을 MVP1 목표로 적용한다. 내용·구조 평가는 계약 변경이 필요한 추가 목표다. [담당 경계와 최신 기준](OWNERSHIP.md)을 우선 확인한다.

목표·담당자는 [OWNERSHIP.md](OWNERSHIP.md), 기술 결정은 [CONTRACT_DECISIONS.md](CONTRACT_DECISIONS.md)를 따른다.

공통 AI 지침·계약 시작점·담당 분리를 공용 토대로 준비했다. 실제 기능은 아래 순서로 담당 영역에 붙인다.

1. 팀 전원이 계약 샘플을 확인한다. HTTP 연결을 바꾸는 담당자는 실제 API·AI 서비스의 접수·STT·콜백 형식과 실패 경로를 검증한다.
2. STT/Vision은 계약을 만족하는 모듈 입출력을 만들고, 강유성이 관찰 신호와 루브릭 계산식을 합의한다. LLM은 점수를 수정하지 않는다.
3. BE는 결과·STT·이벤트 수신 검증을 실제 DB 트랜잭션·내부 서비스 인증·영속 작업 상태와 함께 구현한다.
4. 실제 로그인·동의·프로젝트·영상 DB 업로드, 파일 검증과 Range 재생을 붙인다. 별도 부하·메모리 검증 후에만 500 MiB 지원을 주장한다.
5. Celery/Redis, api 주도 재시도, 콜백 유실·재시작 복구, 삭제·보관 정책을 연결한다.
6. 실제 모델 품질·시간 측정 이후 PDF·실시간 QA를 진행한다.

MVP1 목요일에 2~6을 모두 끝낸다고 가정하지 않는다. 실제 검증된 범위와 미구현 항목을 나눠 시연한다.
