1. 한 건의 영상이 지나가는 경로

프론트는 사용자 API만 호출한다. 분석 서버는 사용자 DB를 직접 수정하지 않는다.

2. 담당별 구현 틀

박재흥 · 사용자·영상 기반

로그인부터 업로드 완료까지

사용자가 자기 영상에만 접근할 수 있는 DB·API 기반을 만들고, 분석을 시작할 수 있는 회차를 인계한다.

① 공통 DB 기반PostgreSQL 연결·세션·migration을 마련한다. ERD v10의 users, auth_sessions, agreements, projects, uploads, rounds를 우선 연결한다. rubrics의 활성 기준 선택은 강유성과 맞춘다.산출물: 연결 가능한 DB 세션, 재실행 가능한 migration, 모델 사용 예시
② 인증·회원·동의가입·로그인·토큰 갱신·로그아웃·내 정보와 동의 상태를 구현한다. 비밀번호 해시, 토큰 보관, 삭제 사용자 차단, USER/ADMIN 권한을 검증한다. 비밀번호 재설정·계정 삭제도 같은 영역에서 명세 순서로 확장한다.경로: /auth/*, /me · 타인 자원 404, 역할 불일치 403
③ 프로젝트·영상 업로드프로젝트 소유권과 활성 루브릭을 확인한다. 업로드 준비→바이너리 PUT→완료 단계에서 크기·해시·실제 미디어 형식·길이를 검증하고 uploads.video_data에 한 번 저장한다. 같은 완료 요청이 회차나 작업을 중복 생성하지 않게 한다.경로: POST /projects/{projectId}/uploads, PUT /uploads/{uploadId}/content, POST /uploads/{uploadId}/complete
④ 영상 접근과 실행 환경사용자 재생용 Range 응답과 AI 전용 영상 스트림의 DB 읽기 기반을 제공한다. 브라우저용 재생 전용 URL 발급을 장민서·FE와 계약에 반영한다. 서비스 환경값과 실행 문서를 정리한다.파일 영역: 새 인증·회원·프로젝트 라우터/서비스, api/services/uploads, api/routers/uploads, api/models, api/migrations, infra/runtime
장민서 · AI·DB·FE 연결

회차 접수부터 리포트 공개까지

AI가 만든 작업 상태·전사·리포트를 현재 회차의 안전한 DB 기록으로 바꾸고, 프론트가 읽을 수 있게 한다.

① 분석 작업 접수업로드 완료된 rounds.id를 analysisId로 사용한다. 최초 attempt=1, 재시도마다 새 jobId를 만든다. 모델·루브릭 버전을 고정해 POST /analysis/jobs로 접수하고 AI 실패를 영속 상태에 남긴다.입력: 유효한 회차 ID·영상 길이·루브릭 버전·목표 시간 · 출력: 영속 작업 ID·QUEUED 상태
② AI 내부 API 수신서비스 인증을 확인하고 GET /internal/analysis-jobs/{jobId}/video, POST .../utterances, POST .../events를 연결한다. 전사는 seq·시각·영상 길이·중복 스냅샷을 검증한다. 이벤트는 현재 attempt·eventId·상태 순서를 검증한다.저장: analysis_jobs, stt_utterances · 잘못된 결과 422, 일시 장애 5xx
③ 최종 결과 저장DONE의 reportKey를 받은 뒤 확정할 AI 내부 GET 결과 API로 Report JSON을 가져온다. 네 점수·버전·근거 시간·STT 완료를 검증한다. reports·report_scores·report_segments를 저장한 트랜잭션이 끝난 다음 DONE을 공개한다.동일 eventId, 이전 attempt, 삭제 회차는 공개 결과를 덮어쓰지 않음
④ 프론트 조회 API소유권을 확인해 상태·실패·전사·리포트를 기존 사용자 API 형식으로 반환한다. 정성 내용·구조 피드백은 합의한 segments·coaching에만 담고, 네 숫자 점수와 contentCheck=null을 유지한다. 실제 응답·오류 예시를 FE 담당자에게 제공한다.경로: GET /projects/{projectId}/rounds/{roundNo}/{status|report|transcript} · 파일: api/clients, api/services/jobs, api/routers/jobs, api/services/results, api/routers/results

3. 서로 넘길 값과 호출 경계

경계주는 사람받는 사람과 행동인계 완료 조건
업로드 완료박재흥: 소유권·파일 검증 후 projectId, roundNo, rounds.id, durationSec, rubricVersion, targetMinutes 제공장민서: 현재 회차에 작업을 한 번 기록하고 AI 접수같은 Idempotency-Key 재호출에 회차·job 중복 없음. AI 접수 실패도 재시작 후 추적 가능
영상 읽기박재흥: 영상 DB 읽기·Range 기반과 삭제/소유권 상태 제공장민서: 현재 job과 서비스 자격 증명을 검증하는 AI 내부 라우터 연결AI만 현재 job의 영상 스트림을 읽고, 삭제·오래된 작업은 거부
AI 결과강유성·이지수: STT·점수·근거·Report JSON 생성장민서: 계약 검증 후 현재 job의 DB 행에 저장STT와 Report 커밋 전에는 공개 상태가 DONE이 아님
프론트 응답장민서: 공개 상태·리포트·전사와 오류 예시 제공이지영·김승혜: Vue API 클라이언트·화면 연결VITE_API_MODE=real에서 실제 응답으로 표시, 목업 응답과 혼동 없음
공용 파일박재흥: DB 기반·api/main.py·환경 파일 정리장민서: 분석 모델 요구사항과 라우터 등록 변경 전달동일 migration 또는 공용 파일을 동시에 수정하지 않고, 병합 순서를 합의

4. 날짜 대신 의존관계로 진행

A

계약을 먼저 잠근다

두 BE·AI·FE 담당자가 새 AI 결과 GET의 경로·응답·인증, 정성 피드백의 segments.kind 값, 재생 URL의 만료·권한을 문서와 계약 모델에 적는다. 기존 v3.5/v1.4 필드명은 임의로 바꾸지 않는다.

B

DB와 업로드를 먼저 잇는다

박재흥이 사용자→프로젝트→업로드→회차까지 만든다. 장민서는 그 사이 AI 클라이언트·콜백 검증을 합성 계약 입력으로 작성할 수 있지만, 실제 완료 판정은 업로드 경계와 합친 뒤 한다.

C

한 회차를 끝까지 흘려보낸다

완료된 회차로 분석 접수→영상 접근→전사 저장→이벤트→Report 저장을 연결한다. 실제 AI 실행 결과만 성공으로 인정한다. 계약 fixture는 형식 확인에만 사용한다.

D

Vue 연결과 실패 경로를 확인한다

프론트 담당자가 실제 서버 모드에서 상태·전사·리포트를 확인한다. 같은 업로드 완료 재호출, 중복/늦은 콜백, 실패 결과, 타인 접근, 영상 구간 이동을 함께 점검한다.

5. 결정된 방향과 남은 세부 계약

사용자 결정

Report 가져오기

AI 서비스에 내부 GET 결과 조회 API를 추가한다. 권장 경로는 GET /analysis/jobs/{jobId}/report. BE는 DONE 콜백의 reportKey를 현재 job과 대조한 뒤 이 API로 최종 JSON을 가져온다.

정확한 경로·응답·오류·보관/삭제는 AI 담당자와 명세에 확정해야 한다. 현재 v1.4에는 이 GET이 없다.
사용자 결정

내용·구조 피드백

새 숫자 점수 없이 기존 segments·coaching에 전사 기반 정성 피드백을 담는다. contentCheck는 계속 null이다.

kind 값, 발화 구간 근거, 문장 작성 주체와 FE 표시 방식은 AI·FE 담당자와 고정한다.
사용자 결정

실제 영상 재생

BE가 짧게 유효한 재생 전용 URL을 발급한다. 해당 회차·사용자에만 묶고 삭제·만료를 검사하며 여러 Range 요청 동안 유효해야 한다.

발급 경로·만료 시간·토큰 전달 형식·로그 노출 방지와 재생 응답은 BE·FE가 계약에 추가한다. 현재 사용자 API v3.5의 Bearer 영상 GET만으로는 <video src> 재생이 안 된다.
다른 미정값: 활성 루브릭의 채점 수치·반올림, 서비스 인증 방식, 500 MiB DB 스트리밍 성능, 보관·실삭제 기간은 추측해 확정하지 않는다. 결정 전에는 관련 경계 밖의 구현을 진행하고, 실제 점수·용량 지원을 검증 없이 완료로 표시하지 않는다.

7. 리뷰 전에 확인할 것

박재흥 체크

  • 회원가입·로그인·동의·프로젝트가 DB에서 이어진다.
  • 타인 프로젝트·영상은 응답하지 않는다.
  • 파일 재전송·완료 재호출에도 영상·회차가 중복되지 않는다.
  • 영상 실내용 검증과 Range 동작을 확인했다.
  • migration 적용·되돌리기와 실행 설정을 공유했다.

장민서 체크

  • 한 회차의 jobId와 attempt가 DB에 남는다.
  • AI 영상 읽기·전사·이벤트는 서비스 인증과 현재 작업을 확인한다.
  • Report JSON과 STT가 저장·검증되기 전 DONE이 보이지 않는다.
  • 중복/늦은/삭제된 작업 콜백으로 결과가 바뀌지 않는다.
  • FE가 실제 API로 상태·전사·리포트를 조회한다.
공통 완료 기준: 한 영상의 업로드부터 실제 AI 결과 표시까지 재현 가능하고, 실패·권한·중복 중 해당 경로를 테스트한다. PR에는 변경 파일·계약 변경·검증 명령·남은 한계를 적는다.
