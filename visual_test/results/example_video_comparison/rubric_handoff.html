Vision → 루브릭 담당자 전달 자료

결론: v3 실험 JSON에 손·얼굴 겹침 후보가 생성된다. 예시.mov의 저장된 5 FPS 검출값을 새 백엔드 사건 생성 코드로 다시 계산해 손 후보 7건, 물건 후보 1건을 확인했다. 21–27초의 실제 양손 정지는 여전히 놓친다. 자동 감점 근거로 확정할 단계는 아니다.

2. 사용하는 모델과 역할

모델Vision에서 받는 값이 JSON에서 하는 일
YOLO11n-pose몸통·어깨·손목 관절양손 정지와 물건 근접 판단. 이번 백엔드 출력의 정지 시간은 이 모델 기준.
YOLO5Face얼굴 박스·5개 특징점얼굴 방향 비율, 손/물건 겹침의 얼굴 영역.
YOLO11n-seg물건 종류·마스크물건과 얼굴 겹침, 손목 근처 동반 이동 후보.
MediaPipe Hand Landmarker (새 입력)손마다 21개 특징점특징점 외곽과 얼굴 박스가 10% 이상 겹친 상태가 0.4초 이상 지속되면 손 가림 후보 생성. 양손 정지 계산에는 아직 사용하지 않는다.

모델 파일은 로컬 경로에서 제공하며 저장소에 포함하지 않는다. Hand Landmarker 경로를 지정해야 새 손 사건이 나온다.

3. 기존 JSON과 변경점

기존 v2이번 v3이유
schemaVersion = vision-observation-v2-experimentvision-observation-v3-experiment사건 종류가 늘어 소비자 계약을 구분한다.
candidateEvents에 물건 후보만 가능HAND_FACE_OVERLAP_CANDIDATE 추가손 가림 근거 구간을 루브릭에 전달한다.
손 모델 입력 없음VisionModelPaths.hand (선택 경로) 및 hands 검출손 영역을 손목 한 점보다 구체적으로 표현한다.
evidence에 손 가림 근거 없음손 후보마다 evidenceId·시간·설명 추가루브릭이 후보 구간과 근거를 연결한다.

가림 확정값, 감점 점수, 시선 제외 사유는 아직 추가하지 않았다. 이번 변경은 후보 사건 생성만 다룬다.

사용자가 확인한 21–27초 양손 정지는 gestureEvents=[], handStillSeconds=0으로 누락됐다. 21.6–23.8초만 연속 정지로 계산돼 5초에 못 미쳤다. 이 영상의 손 후보도 실제 가림 정답과 일치하는 구간/오검출 구간을 개별 검토해야 한다.

얼굴 방향은 판정 가능 49.4초 중 정면 42.0초, 비율 85.02%다. 현재 손 가림 후보를 시선 분모에서 제외하지 않았으며 실제 눈동자 시선도 아니다. 손 정지 판정 가능 8.6초, 영상 전체 62.8초다.

물건과 손의 얼굴 겹침이 같은 44.8–49.0초에 중복 생성된다. 루브릭 담당자는 두 후보를 독립 감점 두 건으로 합산하면 안 된다. 발표 무관 물건 판정은 LLM_NOT_EXECUTED이며 별도 문맥 판단이 필요하다.

6. 루브릭 연결 시 필요한 결정

  1. 손/물건 얼굴 겹침 후보를 실제 감점으로 인정할 검증 기준과 중복 처리 정책.
  2. 가림 구간을 시선 관찰 시간에서 제외할지, 제외한다면 어떤 근거 ID·사유를 전달할지.
  3. 양손 정지 21–27초 누락을 수정하고 새 영상에서 오검출을 확인한 뒤 5초 규칙을 사용할지.
  4. 루브릭 점수는 Vision에서 만들지 않는다. 현재 isScoringReady=false다.

정식 사용자 API·DB Report 계약은 이번 변경 대상이 아니다. 이 v3은 Vision→루브릭 내부 실험 계약이다. 루브릭 소비자가 v2만 허용한다면 v3 사건 종류를 받을 수 있도록 스키마·계약 테스트를 함께 갱신해야 한다.
